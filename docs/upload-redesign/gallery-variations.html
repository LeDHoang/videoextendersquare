Upload redesign · option B · four variations

My media, four ways

Option B makes the page a gallery. These are four ways to lay that gallery out. Each is shown at the same two moments, so they can be compared from the person's side: "I just added three clips" and "I'm back two days later to post one".

Short version

  • Pick 2, Shelves. The page is sorted by what each file needs, so nobody has to read badges to find the next step. The price sits on the shelf where the decision is made, and checking a result gets a large stage.
  • 1, Contact sheet is the baseline from the main report. Efficient, but the preview is small and status is scattered across the grid.
  • 3, To-do list is the clearest about prices and next steps. It reads like an admin table, on a product that is about pictures.
  • 4, Stage and filmstrip has the best preview and is closest to today's page. It shows one file well and the rest poorly.

Screens are drawn at 1440 × 810 in Paper & Ink. Media is stood in for by colour gradients. Credits, lengths, names and dates are example values. Nothing here is built.

From the person's side

The process, in six moments

What a person wants to know at each moment, and what the page must answer. These answers are the same in all four variations; only the layout changes.

1AddDid it take my files?Files appear at once with upload progress. New files are already selected.
2UnderstandWhat happens to them, and what does it cost?One sentence and one total, before any charge. Nothing is spent without a click.
3WaitDo I have to stay?No. Progress shows on the file. It is there on any device when done.
4CheckDoes it look right?Original and square, side by side on a large preview. "Redo" shows its price.
5PostWhat will people see?Title, caption, place. One button. Afterwards, a link to the post.
6LaterWhere is my stuff, and how long do I have?Every file says its state. Square versions say the date they are kept until.

Rules all four follow

  • Just-added files are preselected, and the page states the plan for them. It never starts a paid render by itself.
  • A file that is not yet square says "On this device". It does not show on other devices and is dropped after 6 hours. Square versions follow the account for 30 days.
  • One filled button in the page body: the next step, with the price on it.
  • A file's state is one of four words: Needs square, Working, Ready, Posted.

What differs

  • What the person sees first: everything, a sorted page, a list of steps, or one file.
  • Where the decision sits: a side panel, a shelf, a row, or beside the stage.
  • How large the check is: the preview runs from 232px to 480px.
  • How it copes with many files.
1

Baseline from the main report

Contact sheet and side panel

Every file in one grid, like Explore. A fixed panel on the right acts on whatever is selected. Nothing opens or closes; the person never loses the overview.

For the person

  • Everything stays in view. No dialog, no page change.
  • Switching between files is one click.
  • The post form is always in the same place.

Against

  • To find what needs doing, the person reads ten badges.
  • The check happens on a 232px preview, on a product about immersive video.
  • A panel that changes its whole content with the selection takes learning.

Best when

People handle many files in one sitting and already know the page.

2

Recommended

Shelves, sorted by what's next

The page is grouped by what each file needs. The top shelf is always the one that needs the person. Each shelf carries its own action and its own price. Opening a file brings up a large stage, and arrows step through the shelf.

For the person

  • The page answers "what needs me?" by its order, not by badges.
  • The price is on the shelf, next to the files it pays for, and on each file.
  • Checking gets the largest preview of the four, and arrows make "post, next, post" quick.
  • The same shelves stack on a phone without redesign.

Against

  • The dialog covers the overview while a file is open.
  • Extending only one of three means opening that file, not the shelf button.
  • Fewer tiles fit: one row per shelf, then "Show all".

Best when

People come back after days and need the page to tell them where things stand. That is the "extend now, post later" case.

3

Most explicit

To-do list

One row per file. Each row says, in words, what state the file is in, what it costs and what to do next, with the button on the row. Opening a row expands it in place.

For the person

  • Nothing to decode: every file states its next step in a sentence.
  • Each file's price is in a column, easy to compare before paying.
  • Fits the most files per screen and sorts well by date or name.

Against

  • 46px thumbnails. People recognise their clips by the picture, not the file name.
  • It looks like a file manager, not like the rest of ECHO.
  • A lot of words on screen, which is the complaint this redesign started from.

Best when

People bring many files at once and care most about cost. Closer to a studio tool than a social app.

4

Closest to today

Stage and filmstrip

One file at a time on the large stage the page has today, with the decision beside it. Every other file sits in a strip along the bottom, grouped by state. Arrow keys move along the strip.

For the person

  • The picture is the page. The fill is previewed large before paying, and the result is checked large after.
  • Familiar to anyone who has used a photo app.
  • Smallest rebuild: today's stage and right column stay, the strip is new.

Against

  • The overview is 77px thumbnails. With twenty files the strip scrolls sideways.
  • State is shown by position in the strip, with small labels. Easy to miss.
  • Arriving after two days, the person sees one file, not where everything stands.

Best when

People post one or two files per visit and the look of the result matters most.

Verdict

Recommendation

Build 2, Shelves

  • The request is "extend first, decide later". The hard moment is coming back after days. Shelves are the only layout whose order tells the person where things stand.
  • The price is beside the files it pays for, and repeated on each file.
  • The check, which is where people judge an AI result, gets the largest preview.
  • The dialog reuses today's stage, so the best part of the current page survives.

Take from the others

  • From 4: arrow keys to step through a shelf while a file is open.
  • From 3: the one-sentence state ("Tall video. Its sides will be filled.") as the first line when a file is opened.
  • From 1: multi-select with a total, for extending some but not all of a shelf.

Open questions

  • Should the page notify when a render finishes (a mark on the header's Upload button), or is the shelf enough?
  • When a person posts from the dialog, does it close, or move to the next Ready file?
