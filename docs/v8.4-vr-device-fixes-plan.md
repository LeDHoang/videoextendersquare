## Owner-confirmed interaction model (tandem rig)

- **Locked** = head-locked rig: screen + dock + comments + guide all follow the head transform
  every frame, holding relative offsets. Locking snaps the rig to face the viewer.
- **Unlocked** = world-locked rig: toggling unlock freezes everything in place; looking around
  changes nothing. Grip-drag moves the screen with panels riding along.
- **Orientations**: screen takes the full head quaternion (perpendicular); dock/panels stay
  roll-free (`faceViewerLevel`) so head-tilt never tilts text.

## Workstream 3 — Playback glitch elimination (issue 3) [~done: ☐]

Prime suspects (ranked): (a) overlay 1024² re-render+re-upload ~10×/s during ALL
playback incl. zero comments (v8.3 churn; investigation §0/#4 + Phase 3 flagged this
pattern); (b) three r186 same-size re-uploads ride `texSubImage2D`, the exact path the
investigation proved faulty on this Quest Browser/Adreno build; (c) mipmap regen on
every re-upload (see Workstream 4).

- [x] W3.1 Dirty-only overlay: re-render/re-upload only when the active popup ID-set
  changes or hover changes; fade repaints ≤10 Hz **only while popups are active**;
  zero popups → skip entirely (no `needsUpdate`, mesh hidden). Add
  `renderStats.overlayUploads` counter.
- [x] W3.2 Legacy sampling on ALL `CanvasTexture`s (also the issue-4 fix):
  `minFilter/magFilter = LinearFilter`, `generateMipmaps = false` — video proxy,
  controls, comments, overlay, guide, earth map/label/preview, reticle, glow alpha.
- [x] W3.3 Decisive A/B flag: `WebXRVR.setVideoUploadMode('subimage'|'respec')`
  (+ `?vrTexMode=respec` auto-read in `init()`). `respec` mode disposes the video
  `CanvasTexture` per upload so three is forced down the full `texImage2D` re-spec
  path (legacy behavior). If squares vanish in `respec` → sub-image driver bug
  confirmed → ping-pong becomes the default.
- [x] W3.4 Minimal XR telemetry: per-frame interval + upload counters POSTed ~1 Hz
  to the existing `/api/reels/diag` while presenting (guarded, keepalive).
